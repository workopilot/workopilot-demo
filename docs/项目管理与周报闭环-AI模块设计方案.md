> 本文保留为早期闭环设计。最新菜单和逐页方案以 [项目管理 AI 助理需求与页面设计索引](./项目管理AI助理/README.md) 为准。

## 一、 当前关联文件与模块地图

本项目基于 Vue 3 + Vite + TypeScript + Ant Design Vue + Tailwind CSS，核心业务交互在 `apps/web-antd/src/views/app/mate/` 中以数字员工模式运行。

| 模块环节 | 对应文件路径 | 核心职责与现状 |
| :-- | :-- | :-- |
| **数字员工框架与路由** | `apps/web-antd/src/router/routes/core.ts`<br>`apps/web-antd/src/api/mock-data-mate.ts`<br>`apps/web-antd/src/layouts/mate-app-shell.vue`<br>`apps/web-antd/src/views/app/mate/ai-work/employee-workspace.vue` | 定义了 `pmo-assistant`（交付项目 PMO）与 `project-assistant`（项目助理）等数字员工；交付项目 PMO 顶部提供“对话”、“项目立项”、“项目”和“制度与模板”等入口。 |
| **环节 1：管理者设置 (Templates)** | `apps/web-antd/src/views/app/mate/project-management/pmo/templates.vue` | **项目模板配置**：AI 解析制度文档，抽取产品研发/客户交付/运维服务/销售等各类型的标准阶段、阶段目标、工期、进入退出准则、以及**《必备成果物（Deliverables）》**。 |
| **环节 2：项目立项与工作台** | `apps/web-antd/src/views/app/mate/project-management/pmo/initiation.vue`<br>`apps/web-antd/src/views/app/mate/project-management/projects-workbench.vue` | **项目立项**负责资料上传、AI 解析、宪章确认与基线生成，不设置独立审核步骤；**项目工作台**负责已立项项目的阶段、目标、KR、成果物与执行状态。两者职责解耦。 |
| **环节 3：项目 Mock 数据源** | `apps/web-antd/src/api/mock-project-management.ts`<br>`apps/web-antd/src/types/project-management.ts` | 维护了完整项目树数据（阶段、O、成果型 KR、指标型 KR、健康度状态机、预设的延期/阻塞故事线）。 |

## 二、 全链路闭环架构（业务路径）

从“管理者设置”到“执行中周报汇报”形成四个阶段的良性闭环：

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 管理者设置 (templates.vue)                                │
│    定义项目类型标准阶段、进入退出门禁、必备成果物清单 (Deliverables)  │
└──────────────────────────────┬──────────────────────────────┘
                               │ 实例化与规范对齐
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. 项目创建与排期 (portfolio / project-create-wizard.vue)    │
│    AI 辅助立项，生成：项目 ➔ 阶段 (Stage) ➔ 目标 (O) ➔ KR/成果物 │
└──────────────────────────────┬──────────────────────────────┘
                               │ 计划执行与偏差监控
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. 监控、延期归因与管理者指导 (portfolio - 本次首期实现)       │
│    • 成果物缺失/逾期深度归因 (结合模板退出条件)                   │
│    • 链式影响推演 (推算整体交付延期天数与后续阶段风险)             │
│    • 3 套可执行应对策略 (质询重承诺 / 范围排期调整 / 外部升级)     │
└──────────────────────────────┬──────────────────────────────┘
                               │ 提醒与任务下发
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ 4. 执行中周报汇报与结果反哺 (current-report-workbench.vue)   │
│    • 周五写周报时：AI 提醒“本周有 XX 成果物到期待提交”           │
│    • 周报内嵌“项目目标达成”卡片，汇报进度与成果物               │
│    • 提交后：自动更新 portfolio 中对应 KR 状态与项目健康度       │
└─────────────────────────────────────────────────────────────┘
```

## 三、 首期实现目标：管理者侧 AI 延期与卡点深度指导模块

### 1. 现状痛点

当前 `projects-workbench.vue` 中仅有以下代码逻辑：

- 静态展示 `projectAiGuidance`（一句话检测 + 一句话下一步建议）；
- 点击按钮仅跳往对话 `project-chat`；
- 管理者无法在看板上看到：
  1. 到底是因为哪一个具体的成果物没提交或哪项指标不达标引起的？
  2. 延期会对后续的哪个阶段、整个项目的交付日期造成多大连锁影响？
  3. 管理者现在有什么具体的工具和抓手来解决这个问题？

### 2. 交互落点设计（根据最新反馈优化）

**核心改动：去掉顶部占空的横幅，将入口内嵌至阶段卡片中，增加呼吸光效，点击侧滑出抽屉**

1. **移除顶部横幅**：
   - 去掉原本位于项目摘要下方的 `ai-next-step` 横幅，释放纵向空间，让项目阶段和目标列表更紧凑聚焦。
2. **阶段卡片呼吸光效与行内入口**：
   - 当某个阶段处于 `at-risk`（有风险）或 `blocked`（受阻）时：
     - 阶段卡片边框附带**动态呼吸呼吸光（Pulsing Glow）**与微光环绕动效（橙色代表临期风险，红色/珊瑚色代表严重阻塞）；
     - 阶段头部（标题/状态旁）展示醒目的 **【AI 延期诊断 · 阻碍 O】** 胶囊按钮（带有闪烁粒子图标与风险标签）。
3. **右侧侧滑抽屉（Drawer）**：
   - 点击该阶段的 AI 诊断胶囊按钮，右侧平滑滑出 **【AI 阶段延期诊断与应对指导】** 抽屉，沉浸式展示：
     - **① 卡点深度归因**：明确指明是哪个必备成果物（Deliverable KR）卡住了目标（O），对照模板退出门禁与现场阻塞事实；
     - **② 链式影响推演**：可视化展示本阶段延期对后续关键阶段准入和最终交付日期的链式推迟影响（天数与按期概率变化）；
     - **③ 3 套可执行应对策略**：
       - **策略 1：督促质询与重置承诺**（一键生成质询单与周报补充指令）；
       - **策略 2：范围裁剪 / 容缺推进**（评估非核心成果物后置，自动测算调整后的甘特图工期）；
       - **策略 3：外部依赖升级介入**（针对环境未就绪等外部依赖，生成升级备忘录草稿）。
