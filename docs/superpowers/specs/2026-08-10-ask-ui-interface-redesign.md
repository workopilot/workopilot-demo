# Ask UI 界面重构设计

## 目标

参考用户提供的线索跟进问答界面，将 Ask UI 调整为适合一次处理多道题的紧凑工作台。页面需要在有限视口内稳定展示主题、轮次和提交状态，同时让问题列表独立滚动，并完整保留现有多轮 JSON 工作流。

## 设计方向

采用高保真紧凑布局，而不是只为现有卡片增加吸底按钮。视觉以绿色为主色，使用清晰边框、低阴影和高信息密度，避免装饰性元素挤占问题空间。桌面端优先贴近参考图，移动端保持可读和可操作。

## 页面结构

页面根容器使用 `100dvh`，划分为四个区域：

1. 顶部主题区：展示 Session 标题、说明、状态和亮暗主题开关。
2. 轮次 Tab：展示每轮题数和完成状态，可横向滚动。
3. 问题滚动区：占用剩余高度，只有该区域产生纵向滚动。
4. 底部提交栏：始终固定在容器底部，不随问题列表滚走。

底部提交栏左侧持续展示提交必读说明，中部展示已回答题数和草稿状态，右侧展示主提交按钮。必读说明不要求用户勾选。

## 问题与选项

- 每道题采用紧凑行式布局，保留题号、必填状态、标题、说明和推荐理由。
- 桌面端选项按内容数量使用二至四列网格；窄屏自动降为单列。
- 选中项使用绿色边框、浅绿色背景和明确的选中状态。
- 推荐项继续默认选中，并显示“推荐”标记。
- 文本题保持完整宽度输入区，并显示字数限制。

“其他”作为正式选项参与单选、多选和数量校验。其卡片内部包含补充输入框：点击卡片或聚焦输入框会自动选择“其他”；取消选择会清空补充内容。用户可以只选择“其他”而暂不填写补充信息，必填校验按该选项已选择处理。

AnswerSet 字段结构保持不变，使用保留值 `__other__` 写入 `selectedOptionIds` 表示“其他”已选，补充文字继续写入 `customText`。服务端仅在题目启用 `allowOther` 时接受该保留值。读取旧数据时，如果只有 `customText` 而没有保留值，页面自动按“其他”已选兼容展示。

## 主题模式

右上角提供亮色和暗色切换：

- 首次打开跟随系统 `prefers-color-scheme`。
- 用户主动切换后写入 `localStorage`，后续页面沿用。
- 亮暗模式使用同一绿色强调色和一致的语义层级。
- 所有输入框、边框、文字、弹窗、Toast、历史答案和滚动区域都定义暗色状态。

## 交互与数据流

现有 Session、Round、QuestionSet、AnswerSet 和接口保持不变。页面加载后恢复推荐答案或草稿；每次更改继续进行防抖保存。底栏实时计算“已回答 X / Y 题”。

用户点击“提交本轮答案”后继续打开确认弹窗，展示本轮答案摘要和提交后只读说明。确认成功后当前轮次变为只读，底栏改为已提交状态；后续新 Round 到达时自动切换到新 Tab。

历史轮次保持只读，并可通过 Tab 回看。切换历史轮次时底栏不显示可提交按钮，而显示该轮已处理或已提交状态。

## 响应式规则

- 宽屏：整体最大宽度扩大，选项最多四列，提交栏为横向布局。
- 中等宽度：选项两列，状态信息允许换行。
- 手机：头部和主题开关分行，选项单列，底栏仍锁定并将说明与按钮纵向排列。
- 使用动态视口单位，避免移动浏览器地址栏导致底栏跳动。

## 错误与兼容性

- CDN 中的 Tailwind 不可用时，`fallback.css` 仍能完整呈现布局和主题。
- 服务或草稿保存失败时，底栏显示错误状态，已填写内容不丢失。
- 缺少 Session 或令牌时继续显示独立错误页。
- 不修改 QuestionSet 和 AnswerSet 字段；仅扩展“其他”的保留选项语义，已有 Session 可以直接使用新页面。

## 验收标准

1. 主题区、Tab 和提交栏在页面滚动过程中保持可见，问题区独立滚动。
2. 亮色与暗色可切换、可持久化，并通过可读性检查。
3. 单选、多选、文本题及推荐答案均正常。
4. “其他”可独立选择，也可填写补充内容，提交 JSON 正确。
5. 底栏持续显示提交必读说明、已回答数量和草稿状态。
6. 提交确认、只读历史、多轮 Tab 和自动切换新轮次正常。
7. Node 自测、技能规范校验和浏览器端到端验收通过。
