# Mate 员工工作台精确还原设计

## 目标

将 `/app/mate/employee/:employeeId` 从当前简化聊天页重构为 WiseAI Pharma 员工工作台的完整前端 Demo。最终页面以用户提供的 WiseAI 截图为视觉基准，以以下参考源码为结构和样式依据：

- `E:\work\git2026\agent_platform\wiseai.vue\apps\web-antd\src\layouts\app-shell.vue`
- `E:\work\git2026\agent_platform\wiseai.vue\apps\web-antd\src\views\app\role-console.vue`
- `E:\work\git2026\agent_platform\wiseai.vue\apps\web-antd\src\views\app\digital-employees\chat.vue`
- `E:\work\git2026\agent_platform\wiseai.vue\apps\web-antd\src\views\ai-employee\workbench\index.vue`

目标是迁移参考实现的可见布局、层级、尺寸、状态和主要交互，不再基于当前简化页面进行自由设计。后端、语音通话、流式协议和文件服务继续使用前端 Mock 替代。

## 实现边界

本次重构覆盖：

1. 员工模块二级侧栏。
2. 员工详情页顶部功能导航。
3. 对话历史面板。
4. 聊天标题栏、消息区和业务结果卡片。
5. 快捷问题与消息输入区。
6. 员工、会话和消息的前端 Mock 数据与交互。

保留 `/app/mate` 路由、一级深绿色导航、Pharma Logo、工作台、员工入口页、文件页和自动化页。其他页面不在本次重构范围内。

## 页面总体结构

员工详情路由不再显示当前通用 `MATE WORKSPACE / 普通用户工作台` 顶栏。主内容区域直接采用 WiseAI 的员工角色控制台结构：

```text
一级导航 64px
└── 员工二级栏 256px
    └── 内容区
        ├── 员工功能工具栏
        └── 会话工作区
            ├── 对话历史 308px
            └── 聊天主区
                ├── 聊天标题栏
                ├── 消息滚动区
                └── 快捷问题与输入区
```

内容区外边距为 `16px`，员工功能工具栏与会话工作区间距为 `10px`。工作区占满剩余高度，不出现当前页面大面积无内容的空白状态。

## 员工二级侧栏

二级栏采用 WiseAI `app-shell.vue` 的员工分组卡片结构，不沿用当前“头像 + 姓名 + 角色”的普通列表。

### 顶部区域

- 标题为“数字员工”。
- 右侧提供卡片/列表视图切换。
- 收起按钮位于二级栏与内容区交界处。
- 展开宽度 `256px`，收起宽度 `64px`。

### 员工卡片

- 员工列表按“我的收藏”和“最近联系”分组；没有收藏时仅显示“最近联系”。
- 默认卡片使用半透明白色背景、`12px` 圆角、细绿色边框和轻阴影。
- 卡片间距为 `5px`，内边距约 `8px 10px`。
- 头像为 `36px` 圆形真实图片，右下角显示在线点，左上角显示未读红点。
- 选中员工使用 `#0b6e65` 深绿色背景和白色名称。
- 收藏星仅在悬停或已收藏时显示。
- 点击员工切换到对应 `/app/mate/employee/:employeeId`。

## 员工功能工具栏

工具栏直接迁移 WiseAI `role-console.vue` 的层级与尺寸：

- 高度由内容撑开，约 `84px`。
- 边框为低对比绿色，圆角 `8px`，背景为浅绿到白的横向渐变。
- 左侧第一行显示员工名称和功能胶囊菜单。
- 员工名称字号 `20px`、粗体。
- 功能菜单圆角为胶囊形，默认浅色，选中项深绿色。
- 第二行显示员工业务描述，字号 `12px`。

每名员工提供四个功能标签：一个“数字员工”会话标签和三个符合角色的 Mock 功能标签。数据分析员工显示“数字员工”“数据源”“分析记录”“报表中心”；法务员工显示“数字员工”“合同资料”“审查记录”“风险报告”。其他员工使用同样的四标签结构。本轮只实现标签切换状态；非会话标签显示对应的前端 Mock 摘要面板，不接入真实业务页面。

## 对话历史面板

对话历史面板按 WiseAI 工作台实现：

- 固定宽度 `308px`。
- 位于工作区左侧，与聊天主区处于同一个大圆角容器中。
- 背景为浅灰绿色纵向渐变，右侧有低对比分割线。
- 标题为“对话历史”。
- 标题右侧提供新建、清空和折叠三个圆形图标按钮。
- 会话卡片为白色圆角条目，展示标题、相对时间和选中状态。
- 当前会话使用浅蓝描边和选中圆形勾选图标。

Mock 交互包括：

- 新建会话并自动选中。
- 切换会话，加载对应 Mock 消息。
- 删除单个会话。
- 清空当前员工的全部会话。
- 折叠或展开历史面板。

会话状态按员工分别保存在页面内存中；刷新后恢复初始 Mock 数据。

## 聊天主区

### 标题栏

- 高度约 `60px`。
- 左侧依次显示历史栏开关、`40px` 员工头像、在线点和员工名称。
- 右侧显示历史文件、语音通话和新会话三个圆形图标按钮。
- 历史文件和语音通话使用明确的 Demo 提示；新会话执行真实前端状态变更。

### 消息区

- 占据输入区之外的全部剩余高度，并独立滚动。
- 默认展示与当前员工角色匹配的完整 Mock 对话，不再显示空白白板。
- 用户消息靠右，员工消息靠左。
- 员工消息支持普通文本、编号列表和业务结果卡片。
- 业务结果卡片包含类型标签、标题、摘要和“查看详情”按钮，对应参考截图中的技能卡片。
- “查看详情”显示前端 Modal 或 Drawer，不访问后端。

### 输入区

- 固定在聊天主区底部。
- 快捷问题位于输入框上方，使用小型描边胶囊按钮。
- 输入面板为大圆角矩形，接近截图中的 `30px` 圆角。
- 左下角为附件按钮，右侧为语音和发送按钮。
- 输入消息后立即添加用户消息，短暂延迟后追加员工 Mock 回复。
- 附件和语音操作只显示 Demo 提示，不请求浏览器权限或上传文件。

## 数据结构

在 `src/types/mate.ts` 增加：

- `MateEmployeeMenu`：员工功能标签。
- `MateChatSession`：员工会话标题、时间和未读状态。
- 扩展 `MateMessage`：文本、列表和业务卡片消息。

在 `src/api/mock-data-mate.ts` 为每名员工补充菜单、会话和消息数据。`src/api/mate.ts` 提供查询、新建、删除、清空会话和发送消息的前端 Promise API。

所有数据仍是浏览器会话内 Mock，不接入 WiseAI 的真实接口、鉴权或租户运行时。

## 组件边界

为避免再次把不同职责塞入单个页面，员工工作台拆为：

```text
views/app/mate/
├── employee-chat.vue
└── components/
    ├── employee-console-toolbar.vue
    ├── employee-conversation-history.vue
    ├── employee-chat-header.vue
    ├── employee-message-list.vue
    └── employee-chat-composer.vue
```

`employee-chat.vue` 负责读取路由、协调当前员工/标签/会话和调用 Mock API。子组件只接收清晰的 Props 并发出用户操作事件。

## 响应式

- 宽度大于 `1120px` 时使用参考截图的历史栏 + 聊天主区双栏布局。
- 宽度小于等于 `1120px` 时，历史栏改为从聊天区左侧覆盖展开的抽屉，聊天主区保持可用。
- 宽度小于等于 `768px` 时，功能胶囊菜单允许横向滚动，输入区压缩间距，右侧非核心图标隐藏。
- 不允许页面产生横向滚动。

## 错误与空态

- 员工不存在时跳转到第一名员工，并提示“未找到对应数字员工”。
- 员工没有会话时显示空态，并保留“新建会话”操作。
- Mock API 异常使用 `message.error`，保留当前页面状态。
- 头像加载失败时显示员工姓名首字回退。
- 输入发送期间禁用重复提交，模拟回复失败时保留用户消息。

## 视觉验收

实现后必须使用用户提供的 WiseAI 截图与本地同视口截图进行并排比较，并生成项目根目录 `design-qa.md`。以下差异视为阻塞问题：

1. 员工二级栏仍使用普通列表而非 WiseAI 卡片。
2. 员工详情仍显示通用工作台顶栏。
3. 缺少员工功能胶囊菜单。
4. 缺少 `308px` 对话历史面板。
5. 聊天标题栏、消息滚动区或底部输入区结构缺失。
6. 页面仍以大面积空白作为默认状态。

验收还包括：

- 一级栏 `64px`、二级栏 `256px`。
- 顶部工具栏、工作区圆角、间距和绿色主题与参考一致。
- 员工切换、功能标签、会话新建/切换/删除、快捷问题和消息发送可用。
- Mate 相关 ESLint 通过，生产构建成功。
- `design-qa.md` 最终结果为 `passed` 后才允许交付。
