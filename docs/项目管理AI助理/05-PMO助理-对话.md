# 交付项目 PMO—对话

> 状态：建议方案  
> 当前路由：`/app/mate/employee/pmo-assistant/project-chat`  
> 当前组件：`apps/web-antd/src/views/app/mate/project-management/project-chat.vue`

## 1. 页面目标

让管理者用自然语言跨项目查询风险、原因和建议干预动作，并生成管理材料草稿。页面负责解释和发起动作，不直接替代“管理驾驶舱”“项目治理”和“风险与干预”。

## 2. 与项目助理对话的区别

| 项目助理               | 交付项目 PMO                         |
| ---------------------- | ------------------------------------ |
| 聚焦当前用户参与的项目 | 聚焦授权范围内的项目组合             |
| 回答下一步如何执行     | 回答哪里需要管理者介入               |
| 生成成果物和周报材料   | 生成质询、升级、调整和会议材料       |
| 不能发起管理升级       | 可生成干预方案，但高影响动作仍需确认 |

## 3. 页面结构

- 会话历史：显示查询范围和关注项目。
- 组合上下文：全部项目、部门、单个项目、风险类型。
- 消息流：管理结论、事实依据、制度命中、影响推演、可选动作。
- 输入区：自然语言、附件、推荐问题。

## 4. 核心能力

- 回答“今天最该介入哪三件事”。
- 解释项目为什么有风险及风险是如何变化的。
- 比较多个项目的交付概率、关键依赖和资源冲突。
- 生成质询单、重承诺要求、范围调整建议、升级会议议程等草稿。
- 将对话定位到管理驾驶舱、项目治理或风险与干预页面。

## 5. AI 回答规范

管理类回答至少包含：

1. 风险对象和严重度。
2. 已确认事实和证据来源。
3. 命中的制度、模板或项目宪章规则。
4. 对后续阶段和最终交付的影响推演。
5. 至少一个低影响动作和一个需要人工确认的管理动作。

涉及客户沟通、资源调整、范围变化和管理升级时，只能生成草稿。

## 6. Demo 故事

管理者询问“客户 B 为什么有风险”。交付项目 PMO 指出接口联调报告逾期 2 天、连续两周承诺未兑现、客户环境问题没有正式说明，因此按期概率降至 39%；同时引用制度中的第三段升级规则，并提供“要求补充说明”和“查看完整证据链”两个入口。

## 7. 当前实现与改造点

当前共享组件已按角色返回不同示例回答。后续需：

- 将 PMO 上下文扩展为项目组合和部门范围。
- 统一风险证据与“风险与干预”页面的数据源。
- 对自动提醒与需确认动作使用不同视觉和操作级别。
- 生成材料后进入预览确认，不显示虚假的“已发送”。

## 8. 验收标准

- 从交付项目 PMO 头像进入时默认打开本页。
- 至少演示组合优先级、单项目风险解释、升级材料生成三类对话。
- 每个风险判断都有证据、规则和影响说明。
- 高影响动作必须二次确认，Demo 不真实发送外部消息。
