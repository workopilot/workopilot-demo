# 汇报助理—项目闭环改造

> 状态：建议方案  
> 现有详细文档：[汇报助理与审阅助理产品需求文档](../汇报与审阅助手-产品需求文档.md)  
> 本文只定义汇报助理与项目管理闭环有关的增量改造。

## 1. 改造目标

让周报成为项目执行事实和成果物证据的采集入口，同时保留计划外工作量。周报不是项目管理页面，但其结构化内容必须能被项目助理和交付项目 PMO 消费。

## 2. 本周周报：双轨结构

```text
本周周报
├─ 计划内项目
│  └─ 项目 → 阶段 → Objective → KR
│     ├─ 本周进展
│     ├─ 成果物/证据
│     ├─ Blocker
│     └─ 下周承诺
└─ 计划外工作
   ├─ 临时协作/售前/排障/会议
   ├─ 协作对象与投入
   ├─ 结果或产出
   └─ 是否来源于轻量任务
```

## 3. 计划内项目汇报

- 自动带出当前员工参与项目中的进行中阶段和本人负责 KR。
- 员工选择或确认项目 → 阶段 → O → KR 关联。
- 支持补充本周进展、完成比例、成果物证据、Blocker 和下周承诺。
- 成果物必须显示格式和验收标准；提交周报不等于成果物已验收。
- AI 可根据工作记录和附件建议关联，但员工必须确认。
- 周报提交后，项目页可以读取进展和 Blocker，并将其作为风险证据。

## 4. 计划外工作汇报

- 单独记录不属于项目基线的临时事务。
- 至少包含类型、协作对象、投入、结果和证据。
- 可以引用轻量任务，但不能强制转换成项目 KR。
- 计划外工作用于说明真实负荷和组织协作价值，不应冲高项目进度。

## 5. Blocker 回流

Blocker 字段建议包含：

- 问题事实。
- 影响的项目、阶段或 KR。
- 严重度和预计影响时间。
- 本人已采取的动作。
- 需要谁提供什么帮助。
- 相关证据。

周报提交后，PMO 风险页引用的是 Blocker 事实，不应只引用 AI 摘要。

## 6. “与我相关”与轻量任务

当前“与我相关”主要来自他人周报中的 AI 提及识别。会议提出的 Lightweight Task 是明确下达的临时协作请求，两者概念不同。

建议将页面扩展为“协作任务”，但内部保留两类来源：

- 明确下达：有发起人、接收人、截止时间，支持回复、完成、忽略并说明原因。
- 周报识别：来自他人周报的协助、提问或知会，需要保留原文引用。

该菜单命名和合并方式尚待确认。无论是否合并，不能丢失来源类型。

## 7. 未回复任务联动

- 截止日前仍未回复或未完成的轻量任务，在生成周报时出现在待处理提醒中。
- 员工可以回复、转入下周计划或说明忽略原因。
- 系统不能未经员工确认把任务写成“已完成工作”。

## 8. 与其他页面的数据关系

| 汇报内容       | 消费页面                     | 作用                         |
| -------------- | ---------------------------- | ---------------------------- |
| KR 进展        | 我的项目、项目治理           | 作为执行事实，不直接覆盖基线 |
| 成果物证据     | 成果物、项目详情             | 发起自检或验收               |
| Blocker        | 今日推进、驾驶舱、风险与干预 | 风险证据和行动输入           |
| 下周承诺       | 今日推进、后续周报           | 检查是否兑现                 |
| 计划外工作     | 汇报/审阅页面                | 说明工作量和协作价值         |
| 未回复轻量任务 | 协作任务、本周周报           | 形成回应闭环                 |

## 9. Demo 故事

员工本周周报自动带出“客户 B 集成交付项目—联调阶段—O2—KR2.1”。员工填写进展、上传联调记录并上报客户环境未就绪。周报提交后，成果物页显示新的待确认关联，PMO 风险页显示该 Blocker 和连续两周承诺记录。员工另外记录一次售前演示，作为计划外工作，不影响项目进度。

## 10. 当前实现与改造点

现有本周周报已支持 Markdown、附件、AI 完善、HTML 生成和提交；“与我相关”已支持从他人周报识别事项。后续需：

- 在 Markdown 工作台上方或结构化侧栏增加双轨填报区。
- 建立项目、阶段、O、KR、成果物的关联选择和展示。
- 增加 Blocker 结构化字段和风险回流。
- 保留现有 Markdown/HTML 输出，将结构化数据渲染进周报。
- 明确“与我相关”和轻量任务的来源及状态差异。

## 11. 验收标准

- 一份周报可同时包含计划内项目和计划外工作。
- 计划内项可以追溯到具体 O/KR/成果物。
- 员工确认前，AI 不自动建立项目关联。
- 周报 Blocker 能在 PMO 风险页面被引用并查看原始内容。
- 计划外工作不改变项目进度。
- 未回应轻量任务能在下一周报中形成提醒，而不是自动写为成果。

## 12. 本页不包含

- 项目基线编辑。
- 成果物人工验收。
- PMO 管理干预决策。
- 审阅助理已有完整功能的重复定义。
