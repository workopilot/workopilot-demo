# 交付项目 PMO—项目

> 状态：原“项目”界面已完成一轮局部优化，治理能力仍为建议方案  
> 当前路由：`/app/mate/employee/pmo-assistant/portfolio`  
> 当前组件：`apps/web-antd/src/views/app/mate/project-management/projects-workbench.vue`  
> 当前页面名称：“项目”

## 1. 页面目标

承载已生效项目的组合浏览、项目档案、阶段、目标、KR、成果物和执行状态。它回答“项目当前推进到哪里、是否仍按已确认基线执行、哪些事项需要干预”。立项前的资料上传、AI 解析和宪章确认统一放在独立“项目立项”页面。

## 2. 页面结构

```text
项目
├─ 项目组合列表
│  ├─ 搜索、类型、状态、负责人筛选
│  └─ 健康度、当前阶段、下个门禁、宪章状态
├─ 项目摘要
│  ├─ 当前阶段与总体进度
│  ├─ 阶段、Objective、KR 与成果物
│  └─ 最新风险与变更
└─ 项目详情
   ├─ 基本规划与商业目标
   ├─ 阶段全景
   └─ 已生效项目宪章
```

## 3. 与“项目立项”的边界

- “项目立项”负责生效前：项目资料、AI 解析、宪章确认和基线生成。
- “项目”负责生效后：按已确认基线推进阶段、目标、KR、成果物和风险处置。
- 项目立项完成后，通过“进入项目执行”跳转到本页。
- 本页可查看已确认宪章和基线版本，但不承担首次宪章确认。
- 执行中发生范围、工期、责任或验收标准变化时，本页生成变更草稿；变更审批能力后续逐页确认。

立项页详细需求见 [07A-交付项目PMO-项目立项.md](./07A-交付项目PMO-项目立项.md)。

## 4. 项目宪章内容

- 项目目的、范围和不在范围内事项。
- 商务合同/SOW编号及关键交付承诺。
- 里程碑、阶段和依赖。
- RACI 责任矩阵。
- 人力、预算、环境和外部资源需求。
- 成果物格式、验收标准和验收责任人。
- 风险升级、变更和容缺处理机制。
- 批准人、批准时间和当前生效版本。

## 5. 项目基线与变更

- 项目宪章批准后形成项目基线。
- 执行中的实际进展不能覆盖基线计划。
- 修改阶段、目标、交付日期、责任人或验收标准时，应生成变更草稿。
- 变更批准后产生新基线版本，并记录原因、影响和批准人。
- Demo 至少展示“当前基线”和“一次待确认变更”。

## 6. 项目组合列表

列表需展示：项目名称、类型、负责人、宪章状态、当前阶段、健康度、下个门禁、按期概率。点击项目进入完整 Context：宪章、阶段、O/KR、成果物、风险、证据和变更记录。

## 7. Demo 故事

“客户 B 集成交付项目”已经从“项目立项”发布基线。交付项目 PMO 在本页看到当前阶段、目标、KR 和成果物，进入项目详情查看已生效宪章；当接口联调报告逾期时，从阶段侧滑查看 AI 风险归因和干预建议。

## 8. 当前实现与改造点

当前页面已提供项目筛选、项目摘要、O/KR 层级、成果物和阶段侧滑；AI 立项入口已迁移到独立“项目立项”页面。后续需：

- 保留原项目界面和信息结构，以局部增强为主。
- 增加基线版本和待确认变更的明确提示。
- 让目标、KR 和成果物与周报结构化回写打通。
- 增加变更草稿和版本记录。

## 9. 验收标准

- 只展示已立项项目，不再提供首次立项入口。
- 能查看项目的已生效宪章和稳定基线版本。
- 能从项目定位到当前阶段、目标、KR、成果物和风险。
- 变更不会直接覆盖已批准基线。
- 项目组合与详情的状态一致。

## 10. 本页不包含

- 全局制度文件维护。
- 单项目资料上传、AI 解析和首次宪章审批。
- 执行者日常优先级。
- 周报编辑。

## 11. 当前确认结论

- 保留原“项目”页面的信息架构和视觉设计，继续使用共享的 `projects-workbench.vue`。
- 从本页移除“AI 立项”入口，新增独立“项目立项”菜单和页面。
- 不将页面改造成独立的“项目治理”工作台，也不新增项目组合、宪章待确认、基线变更三级页签。
- 本文第 1～10 节继续作为业务能力规划资料；未来若要补充宪章、基线或变更能力，应优先在原页面结构上做局部增强，并逐项确认后再开发。

## 12. 已确认的局部界面规则

- “项目详情”和“项目宪章”属于同一项目档案，不再设置两个按钮和两个抽屉页签。
- 主页面只保留“项目详情”入口；抽屉按“基本规划 → 商业目标与范围 → 阶段全景 → 项目宪章”连续展示。
- 阶段侧滑中的阶段概述、项目周报和 AI 建议内容全部保留，不改变原有业务策划。
- 阶段侧滑统一使用白色内容卡、浅灰绿色页面底和品牌绿色交互色；橙色与红色只表达延期、预警、阻塞及容缺等异常语义。
- 抽屉在窄窗口下使用全宽布局，侧栏导航转为顶部横向导航，指标卡与策略卡自动改为两列或单列。
- 项目摘要下方的“阶段流转全景”默认收起，标题右侧提供明确的展开/收起按钮。
- 展开后以一条横向连接线在卡片背后串联各阶段，连接线只在卡片之间露出，不穿过卡片内容；每张卡片仅显示阶段名称和“X月X日完成”的计划日期。
- 已完成、进行中和未开始卡片分别使用浅绿、浅蓝和浅灰背景，阻塞状态叠加浅红风险语义；绿色不再同时承担“已完成”和“进行中”两种含义。
- 里程碑卡片保留原阶段快速切换能力；窄屏允许里程碑区域内部横向滚动，不挤压下方阶段详情。
- 下方可折叠阶段列表的标题顺序固定为“阶段 N → 阶段名称 → 小状态标签”；阶段名称提高字号，并用绿、青绿、灰和红区分已完成、进行中、未开始和阻塞状态。
- 阶段不能通过单击直接切换。点击里程碑卡片、阶段启动按钮或侧滑中的激活入口后，统一弹出“确定要手动切换状态吗？”浅色确认弹窗；确认后才重算前后阶段状态与项目进度。
- 阶段侧滑中的项目周报按月份折叠并支持按姓名、周次和标题搜索；每份周报压缩为“头像 + 人名 + 标题 / 周次 + 日期 + 异常”的两行小卡片，详细摘要、进度、成果物和卡点通过点击卡片后查看。
- AI 建议不显示“抢回多少天”等精确收益承诺；阶段已延期时明确显示“已延期一次 · 再次延期将上报总经理”。
