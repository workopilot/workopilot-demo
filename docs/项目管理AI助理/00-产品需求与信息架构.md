# 产品需求与信息架构

> 状态：需求基线；菜单明细仍待逐项确认  
> 关联背景：[项目管理制度数字化与AI助理应用改造方案.md](../项目管理制度数字化与AI助理应用改造方案.md)

## 1. 产品目标

本 Demo 要表达的不是通用项目管理工具，而是一套由制度驱动、由 AI 辅助、由人最终负责的项目治理闭环：

- 把制度和项目经验转成可执行的阶段门禁、成果物标准和异常流程。
- 用合同/SOW和内部制度共同生成项目宪章与项目基线。
- 让项目执行围绕 Objective、KR 和 Deliverable，而不是只维护任务完成率。
- 让周报成为项目事实和证据的采集入口，而不是孤立的文字汇报。
- 让 AI 风险提示能够说明原因、引用证据、给出动作，但不越过人工授权。
- 记录计划外工作和轻量协作，不强迫所有工作进入项目结构。

## 2. 用户角色

| 角色 | 核心诉求 | 主要入口 |
| --- | --- | --- |
| 交付部门负责人/PMO | 维护制度、模板和治理规则，判断项目组合风险 | 交付项目 PMO |
| 项目经理 | 发起立项、确认宪章、维护基线、处理风险 | 交付项目 PMO、项目详情 |
| 项目成员 | 知道今天应推进什么，提交成果物和项目进展 | 项目助理、汇报助理 |
| 协作任务发起人 | 轻量下达临时协作并获得回应 | 汇报助理/个人助理 |
| 审阅人 | 审阅周报并提出需要后续跟进的问题 | 审阅助理 |

## 3. 核心对象关系

```text
制度文件 ──生成/更新──> 项目模板 ──实例化──> 项目宪章
                                             │
                                             ▼
                                         项目基线
                  ┌──────────────────────────┼──────────────────────────┐
                  ▼                          ▼                          ▼
                阶段                      Objective                     RACI
                  │                          │
                  │                          ▼
                  │                          KR
                  │                          │
                  └────────门禁/验收─────────┤
                                             ▼
                                          成果物
                                             │
                                             ▼
                                      证据/周报/验收结果
                                             │
                                             ▼
                                      风险信号与管理干预
```

重要边界：制度文件是全局治理来源；合同/SOW是单个项目的来源。二者不能混成同一类上传资料。

## 4. AI 与人工的责任边界

AI 可以：

- 解析制度、合同和项目资料。
- 建议缺失条款、阶段、O/KR、成果物和验收标准。
- 汇总事实，识别风险信号，推演影响。
- 生成提醒、质询、会议议程、补救计划等草稿。

AI 不可以：

- 未经人工确认发布制度模板。
- 未经人工批准让项目宪章生效。
- 将猜测或低置信度识别当成事实。
- 自动发送高影响管理材料或擅自调整项目基线。
- 用“AI 判断”替代来源证据、制度条款或责任人决策。

## 5. 关键状态

| 对象       | 建议状态                                       |
| ---------- | ---------------------------------------------- |
| 制度解析   | 待解析、解析中、待确认、已确认、解析失败       |
| 项目模板   | 草稿、待确认、已发布、有缺口、已停用、已归档   |
| 项目宪章   | 草稿、待批准、已批准、生效中、已替换           |
| 项目健康度 | 正常、需关注、有风险、受阻                     |
| 成果物     | 未开始、准备中、待验收、已通过、需整改、已逾期 |
| 轻量任务   | 待回应、已回复、已完成、已忽略、已逾期         |
| 管理干预   | AI 建议、待确认、执行中、已完成、已取消        |

## 6. 跨页面一致性要求

- 同一个 Objective、KR、Deliverable 在项目助理、交付项目 PMO 和汇报助理中使用同一名称和状态。
- 所有 AI 风险都至少展示“事实证据、命中规则、影响对象、建议动作”四类信息。
- 所有项目调整都应区分“建议”和“已生效基线”。
- 计划外工作可以关联轻量任务，但不能伪装成项目 KR。
- 周报提交的成果物只是证据或待验收版本，不能自动标记 KR 已完成。
- 高影响动作必须保留人工确认界面和决策记录。

## 7. Demo 范围

本阶段实现前端 Mock 流程：

- 支持代表性样例数据和完整状态切换。
- 支持页面之间携带项目、阶段、KR、成果物或风险上下文跳转。
- 支持模拟 AI 解析、生成和建议过程。
- 不实现真实 OCR、大模型调用、文件持久化、消息发送、日历协调和生产级权限系统。

## 8. 总体验收故事

1. 交付项目 PMO 上传一份制度，AI 识别阶段规则并提示缺少验收失败流程。
2. 交付项目 PMO 修改建议并发布一个新模板版本。
3. 项目经理上传合同/SOW，选用模板并生成项目宪章草稿。
4. 人工确认宪章后，项目成员在“我的项目”和“今日推进”中看到阶段目标和成果物要求。
5. 成员在周报中关联 KR、提交成果物证据并上报客户环境阻塞。
6. 交付项目 PMO 在“风险与干预”看到证据链、制度依据和延期影响，确认生成升级会议议程。
7. 后续周报展示干预动作的执行结果，形成可追踪闭环。
