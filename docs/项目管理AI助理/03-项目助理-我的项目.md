# 项目助理—我的项目

> 状态：建议方案  
> 当前路由：`/app/mate/employee/project-assistant/projects`  
> 当前组件：`apps/web-antd/src/views/app/mate/project-management/executor/projects.vue`

## 1. 页面目标

让项目成员从“我参与哪些项目”进入项目上下文，并清楚看到本人负责的阶段、Objective、KR、成果物和风险。成员看到的是执行视角，不承担 PMO 的模板发布和项目组合治理。

## 2. 页面结构

- 项目筛选：全部、进行中、需关注、有风险、已完成。
- 项目卡片：项目名称、本人角色、当前阶段、健康度、下一里程碑、本人待交成果物。
- 项目详情入口：进入独立详情页查看完整项目 Context。
- 视图切换：首期以卡片/列表为主；甘特图仅在有助于说明阶段关系时使用。

## 3. 项目详情层级

```text
项目概况
├─ 项目宪章摘要
├─ 阶段与门禁
├─ Objective
│  └─ KR
│     └─ Deliverable / Metric
├─ 责任关系
├─ 风险与阻塞
└─ 讨论和证据时间线
```

默认突出当前用户负责或参与的对象，允许切换为完整项目视图。

## 4. 关键交互

- 按角色、状态和项目类型筛选。
- 点击 KR 查看目标说明、权重、期限、证据和成果物。
- 点击成果物进入“成果物”页面处理。
- 点击风险查看事实依据，但普通成员不能执行 PMO 级管理升级。
- 在项目上下文中发起对话，项目助理自动携带当前项目和对象。

## 5. 权限边界

- 项目成员可以更新本人负责 KR 的事实进展、补充证据和上报 Blocker。
- 项目成员不能直接修改已批准的项目宪章、阶段门禁或责任矩阵。
- 基线调整应发起变更申请，由项目经理或 PMO 确认。

## 6. 当前实现与改造点

现有页面已提供项目卡片。执行者页面不应主动承担“AI 立项”，该动作统一放在交付项目 PMO 的“项目立项”。本页需补充：

- 本人角色和本人负责对象。
- 下一里程碑和待交成果物。
- 宪章/基线只读摘要。
- 与成果物、周报和项目对话的上下文跳转。

## 7. Demo 故事

员工进入“客户 B 集成交付项目”，看到自己是接口负责人，当前位于联调阶段，负责 KR2.1；联调测试报告处于“需补全”，并且客户环境是外部阻塞。点击成果物后进入自检和提交流程。

## 8. 验收标准

- 只展示当前用户参与的项目。
- 项目卡片能区分项目健康度和本人行动状态。
- 能从项目逐级定位到当前阶段、O、KR 和成果物。
- 执行者不能直接改动已批准项目基线。

## 9. 本页不包含

- 全公司项目组合管理。
- 制度与模板配置。
- 项目宪章批准。
