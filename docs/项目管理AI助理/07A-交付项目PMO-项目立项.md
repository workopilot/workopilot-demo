# 交付项目 PMO—项目立项

> 状态：Demo V1 已实现  
> 路由：`/app/mate/employee/pmo-assistant/initiation`  
> 组件：`apps/web-antd/src/views/app/mate/project-management/pmo/initiation.vue`

## 1. 页面目标

将单项目资料、部门制度和项目模板汇总为可确认、可追溯的项目宪章，并在管理者确认后生成项目基线。“项目立项”负责生效前流程，“项目”页面负责生效后的执行管理。

## 2. 页面结构

```text
项目立项
├─ 管理模式
│  ├─ 状态概览：待补资料 / 待 AI 解析 / 待确认宪章 / 草稿总数
│  └─ 未生效草稿列表：搜索、状态筛选、项目状态、继续立项
└─ 引导创建模式（点击“新建立项”或“继续立项”后进入）
   ├─ 1 项目资料
   ├─ 2 AI 解析
   ├─ 3 结构与宪章
   └─ 4 项目基线
```

## 3. 四步流程

1. 项目资料：提供一个支持多选的批量上传入口，不按资料类型逐项上传。系统根据文件名和内容模拟自动分类，并立即解析、填充项目基本信息。所有资料均为选填；不上传时项目基本信息默认为空，也允许直接进入下一步。项目目录可选且可以为空。
2. AI 解析：提取范围、阶段、里程碑、交付物、资源和约束，明确合同缺口与制度补全依据。
3. 结构与宪章：先确认 AI 生成的项目阶段及每阶段目标，再确认范围边界、里程碑、RACI、资源、成果物验收标准和异常机制。
4. 项目基线：上述内容经管理者确认后直接生成只读 V1.0；后续调整以变更草稿形成新版本，不再设置独立审核步骤。

## 4. Demo 交互

- 支持按状态筛选和搜索立项记录。
- 管理模式只展示草稿，不同时展开编辑工作区。
- “新建立项”创建待补资料草稿并进入独立四步向导；点击现有草稿的“继续立项”从已完成进度继续。
- 向导统一由底部“上一步 / 下一步”推进，尚未到达的步骤不可跳转，当前草稿自动保存。
- 支持本地选择文件并模拟 AI 解析进度；Demo 不上传文件到服务器。
- 第一步不再增加“提醒上传/资料到达/自动生成”等页内步骤引导，批量上传区域本身承担操作引导。
- 左侧为紧凑资料收集卡，只保留资料类型提示、一个批量上传入口和自动分类结果；右侧为主要的“项目基本信息”卡，并显示空白、识别中、已生成三种状态。
- 未上传任何资料时，“下一步：AI 解析”仍然可用，项目基本信息也允许手动填写；上传任意资料后自动填充 Demo 默认数据。
- 项目基本信息分为“项目识别信息”和“组织与治理设置”，包括项目名称、编号、客户、项目类型、计划交付日期、项目目录、项目经理、适用模板和项目目标摘要；项目目录可为空。
- 阶段名称、阶段目标和 RACI 责任矩阵都可以在生成基线前编辑；调整后必须重新确认。
- 宪章必须分别确认阶段/目标、范围/成果物和 RACI/资源，之后直接生成项目基线。
- 列表只保留尚未生效的草稿；基线生成后从草稿列表移除，短暂展示项目基线交接页，并可进入“项目”执行页面。
- 资料、AI 生成项和人工修改均可通过右侧浅色抽屉查看来源与过程留痕。

## 5. 复用边界

- “交付项目 PMO”是交付部门的数字员工实例。
- 底层“项目 PMO”能力、四步状态机和页面组件保持通用。
- 其他部门复用时只替换制度来源、项目模板、阶段术语、成果物标准和确认角色，例如“研发项目 PMO”“产品项目 PMO”。

## 6. 视觉规则

- 使用 WorkoPilot 青绿色浅色设计系统，不采用新的蓝灰企业配色。
- 页面背景 `#F8FBFA`，卡片和抽屉使用白色；主按钮使用品牌绿色，禁止黑色或默认蓝色主按钮。
- 黄色/橙色只用于待确认和治理缺口，红色仅用于阻塞或危险操作。
- 桌面管理页采用全宽草稿卡片列表，创建页采用全宽单条向导；窄窗口下卡片改为单列，步骤栏可横向滚动。
- 立项第一步桌面端采用“较窄资料卡 + 较宽项目基本信息卡”，820px 以下再切换为上下布局。

## 7. 草稿与已生效项目边界

- 本页面是“生效前工作队列”，只显示资料准备、AI 解析和待确认中的立项草稿。
- 项目基线发布后，该记录不再占用立项列表；后续阶段、目标、KR、成果物和风险均在“项目”页面管理。
- 基线发布成功页作为一次性流程交接状态保留，用户点击“进入项目执行”跳转到“项目”页面。

## 8. 本页不包含

- 已生效项目的阶段、O/KR 和日常执行编辑。
- 全局制度文件解析与项目模板发布。
- 文件服务、OCR 和真实大模型调用；当前上传只保留本地文件名并模拟识别结果。
