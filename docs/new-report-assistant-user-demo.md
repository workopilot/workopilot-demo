# 新汇报助理：用户侧 Demo

## 页面结构

- 数字员工新增「新汇报助理」，保留原汇报助理。
- 第一菜单「对话」：`/app/mate/employee/new-report-assistant/report-chat`，左侧历史、右侧聊天；第二菜单「汇报」：`/app/mate/employee/new-report-assistant/reports`。
- 汇报首页：管理员开放方案的紧凑卡片，桌面端一行四个，包含个人周报、个人日报、项目周报、客户月报；用不同颜色的大图标快速区分，提供轻量阴影与悬停微动效，窄屏降为两列或一列，尊重减少动画设置。支持搜索和无结果提示。
- 方案与业务类型分离：卡片是具体汇报方案，个人日报/周报同属个人报告。未开放的产品线方案不展示。
- 员工汇报页面：顶部周期选择，周报选周、日报选日期、月报选月份；左侧文章导航，中间来源正文，右侧 AI 建议，文末补充、下一步计划和风险诉求。
- 文章导航按工单、项目、任务、Git、需求、文件与其他定位，可查看原始记录快照。窄屏下目录横向收纳，辅助建议移至正文下方。
- 员工页不包含「收到的汇报」或审核他人报告；审阅属于独立页面的职责。

## 核心交互

1. 选择方案，直接读取该方案预生成的示例草稿，各方案使用不同成果、指标和来源。
2. AI 总结与来源事实只读，来源按钮打开演示快照；人工补充、下一步计划、风险诉求可以编辑并保存。
3. 重新总结生成候选，确认采用前不替换正文；采用后保留原版本与人工补充。
4. 下一步计划的演示匹配支持已有 Demo 任务、部分覆盖的接口联调任务、未匹配任务三条路径。匹配仅基于示例关键词和样本，不是实际 AI 检索。
5. 先独立确认向项目披露素材，再确认任务关联/子任务补充/创建；关闭弹窗不执行任务。同条计划避免重复执行。
6. 提报弹窗分别选择分享对象和指定反馈人；可以只分享，不指定反馈人。显示分发记录，不发送真实消息。
7. 已提报报告修改人工补充后形成更新草稿，重新确认后才分发；保留已提报快照。后续真实版本反馈重开规则仍需评审。
8. 对话定时演示解析「每周几 HH:mm」，展示北京时间和覆盖周期，确认保存后更新界面。未运行定时服务。
9. 齿轮打开本报告的数据源配置，允许开启或关闭管理员开放的数据源。「需求」开关控制是否纳入需求素材；保存后生成新版本，人工补充与计划保留。
10. Git 默认待授权。确认只读范围后可完成模拟授权，无需真实账号或令牌；保存配置后纳入示例提交。不开启或未授权时，正文与目录明确显示原因。
11. 周期切换保存当前人工草稿；不同周期使用独立内容，不将已有成果复制到新周期。没有样本的周期显示空状态，允许手工补充。

## 实现与边界

- Vue 3 + TypeScript + Ant Design Vue，接入现有数字员工路由与菜单。
- 数据在 `src/api/mock-new-reports.ts`、`mock-report-materials.ts` 与 `mock-report-chat.ts`；演示状态保存在内存，刷新重置。
- 不接入真实 AI、源业务系统、任务写入、消息分发、后台配置或定时调度。
- 当前每个开放方案预置一期有素材的报告，其他周期建立空草稿。真实多周期数据、Git OAuth、管理员配置、完整对话解析、文件上传与导出留待后续接入。
- 不增加部门报告、多级审批或通过票数规则。

### 项目周报、客户月报场景设计（2026-10-22）

本轮以最新会议纪要为需求基线，并按用户补充明确：项目经理负责项目报告的审查和补充，客户经理负责生成、审查客户报告。以下页面结构、逐节核对及阶段示例属于产品设计方案，不新增会议未约定的审批层级。

| 报告 | 回答的问题 | 主数据与数据来源 | 审查人 |
| --- | --- | --- | --- |
| 项目周报 | 当前阶段、本周计划完成情况、成果与交付、承诺与预测、风险与协调、下周目标 | 单个项目 → 项目任务、里程碑、工单、成果物；已确认披露的项目素材为补充 | 项目经理 |
| 客户月报 | 解决了什么问题、项目是否按期交付、客户得到什么价值、哪些事项需要配合、下月做什么 | 单个客户 → 已关联交付项目及运维服务项目 → 项目任务、工单、巡检、回访、验收与交付物 | 客户经理 |

#### 项目经理编辑与预览

编辑页显示项目范围、项目经理身份、当前阶段及 AI 整理的项目结论。四个审查章节为「本周完成与交付」「阶段、里程碑与交付」「风险与协调」「下周目标与计划」。AI 总结只读，可重新生成；项目经理可以补充判断、预计验收日期、风险原因、协调诉求、计划和附件。原始事实错误应回业务系统修正后重新采集。

预览按管理者阅读顺序呈现：整体结论 → 本周与累计指标 → 阶段路径及累计任务完成图 → 里程碑计划与实际对照 → 成果卡片 → 风险协调 → 下周计划。累计任务完成比例不解释为项目整体进度；预测日期不自动替代项目基线。

#### 客户经理编辑与预览

客户月报不直接套用项目周报或员工周报。Demo 提供以下独立阶段示例，各自有项目范围、事实快照、审查补充与核对状态。

| 客户关联项目阶段 | 重点内容 | 预览表达 |
| --- | --- | --- |
| 建设交付期 | 当前阶段、约定交付物、接口/任务完成、原承诺日期与预计日期、延期原因、客户配合事项 | 交付指标、阶段路径、里程碑对照、交付成果、风险与下月计划 |
| 上线交接期 | 上线结果、验收清单、培训资料、遗留问题、服务交接条件 | 上线与验收分别展示；突出未签收事项和运维接手条件 |
| 运维服务期 | 受理与解决问题、未闭环问题、响应时效、巡检、满意度、关联项目历史交付、下月改进 | 服务指标、问题解决进度与分类条形图、历史交付与本期服务分离、风险与服务计划 |

运维示例为 30 个本月受理问题，其中已解决 28 个、跟进中 2 个；分类 14 + 8 + 8 = 30。4 次巡检、12 份有效问卷、满意度 4.8/5。历史项目 8 月验收不会计入 9 月新增交付。不同阶段下使用同一客户的不同关联项目示例，不代表可以直接修改真实客户生命周期。

实际产品中，阶段应来自关联项目事实。同一客户若同时有建设项目和运维项目，应在一个客户报告内分段呈现各项目阶段与成果，不把整个客户强制归为单一阶段；本 Demo 用场景切换展示三种模板。

#### 审查、后续行动与分发

- 编辑与预览同页切换；预览前保存，审查文本、附件和事实快照使用同一报告版本。
- 每节可查看依据、重新整理并补充；重新生成保留人工文本和附件，受影响章节需要重新核对。
- Demo 用四节核对清单表达负责人审查责任，核对完成后进入现有分发中心；这不是多级审批或投票。
- 计划先检查已有任务或工单，区分关联、补充子任务、新建任务；自由文本匹配仅作演示建议，执行前必须人工核实并确认。
- 普通分享对象无需强制反馈；指定反馈人必须评分并写意见。已提交内容锁定，保留版本与分发记录。
- 客户报告限于当前客户关联项目；不提供跨客户 PMO 总览，不直接写入飞书，也不自动产生收费决定。
- 空周期不沿用其他周期的业绩指标与结论。当前为前端会话 Demo，刷新后重置。
