# AI Work Review · 周报 Demo 重构规划（员工侧 · 焦点版）

> 聚焦：**员工如何生成周报、如何查看周报，以及周报关联的评价与回复体系**。设计基础：保留「数字员工（Agent）」主导菜单的产品架构。

---

## 一、核心架构：对话层 vs 后台 Agent 层

这是整个产品最关键的架构区分：

```
┌──────────────────────────────────────────────────────────┐
│  对话层（用户可见 · 数字员工）                              │
│                                                          │
│  数字员工 = 对话 / 查询 / 调用工具 的交互入口                 │
│  ┌────────────────────┐    ┌────────────────────┐        │
│  │ 周报助理            │    │ 周报审核            │        │
│  │ 服务员工            │    │ 服务管理者          │        │
│  │ · 聊天沟通          │    │ · 聊天沟通          │        │
│  │ · 查询工作资料      │    │ · 查询团队周报      │        │
│  │ · 调用工具生成周报  │    │ · 调用工具查看分析  │        │
│  └─────────┬──────────┘    └─────────┬──────────┘        │
│            │                         │                    │
│            └──────────┬──────────────┘                    │
│                       ↓ 调用                              │
├──────────────────────────────────────────────────────────┤
│  后台 Agent 层（用户不可见 · 自动运行）                     │
│                                                          │
│  这些是自动运行的"工人 Agent"，数字员工调用它们、呈现它们的结果 │
│  ┌─────────────┐ ┌──────────────┐ ┌──────────────────┐   │
│  │ 生成 Agent   │ │ 完整度 Agent  │ │ 评分/洞察 Agent    │   │
│  │ 聚合资料     │ │ 检查完整度    │ │ 综合评分          │   │
│  │ 生成草稿     │ │ 识别缺失      │ │ 挖掘模式(连续跟进) │   │
│  │              │ │ 提醒补全      │ │ 给方案/追问建议   │   │
│  └─────────────┘ └──────────────┘ │ 逐项评价          │   │
│                                  └──────────────────┘   │
└──────────────────────────────────────────────────────────┘
```

### 1.1 关键区分

|  | 数字员工（对话层） | 后台 Agent（自动层） |
| --- | --- | --- |
| **可见性** | 用户可见，有头像、人格、菜单 | 用户不可见，自动运行 |
| **职责** | 查询、聊天、调用工具 | 生成草稿、检查完整度、评分、挖掘问题 |
| **做不做评分** | **不做**，只呈现结果 | **做**，自动评分 |
| **关系** | 是工具的**调用者**和结果**转述者** | 被调用的**执行者** |

**一句话**：数字员工是「**面向人的沟通界面**」，评分/生成/挖掘这些重活是「**后台自动跑的 Agent**」。数字员工调用它们，然后把结果用人话讲给用户听、或在页面上呈现。

### 1.2 在 Demo 里的体现

- 员工对周报助理说"帮我生成本周周报" → 周报助理**调用生成 Agent** → 草稿生成 → 周报助理转述"草稿好了，完整度 78%"
- 页面上的"完整度 78%"和提醒，是**完整度 Agent 后台跑出来的结果**，周报助理只是把它展示出来
- 主管看到的"评分 4.2 + 挖掘出连续跟进无进展"，是**评分 Agent 后台跑出来的**，周报审核只是查询并呈现

> **Demo 实现技巧**：后台 Agent 不需要真的实现，它的"产出"作为**预置数据**存放在 Mock 里（评分、完整度分析、模式挖掘结论都是预先生成好的）。数字员工/页面的职责是**把这些数据自然地呈现**，并在对话里表现得像是"刚调用工具拿到的"。

### 1.3 两个数字员工的人格

虽然评分是后台做的，但两个数字员工在**呈现方式和服务对象**上仍然不同——这正是用「数字员工」隔离菜单的价值：

|  | 周报助理（weekly-assistant） | 周报审核（weekly-review） |
| --- | --- | --- |
| **服务对象** | 员工 | 管理者 |
| **能调用的工具** | 生成 Agent、完整度 Agent、资料查询、工作记录查询 | 评分 Agent、洞察 Agent、团队周报查询、证据穿透 |
| **呈现什么** | "你的草稿好了，完整度 78%，这两项要补充" | "张三连续 3 周写'持续跟进'无进展，评分 3.0，建议面谈" |
| **语气** | 温暖的帮手 | 严谨的参谋 |

## 二、周报的本质：四要素聚合

一份周报不是凭空写的，而是**本周所有工作资料的聚合产物**。根据需求，一份周报包含四个要素：

```
一份周报 = 事项 + 关联资料 + 下周计划 + 实体关联

┌─────────────────────────────────────────┐
│  本周周报（第 32 周）                     │
│                                         │
│  ① 本周事项（按类分组）                    │
│     ├─ 本周成果                          │
│     ├─ 主要工作                          │
│     ├─ 问题与风险                        │
│     └─ 需要协助                          │
│                                         │
│  ② 关联资料（每个事项可穿透查看原始资料）     │
│     ├─ 文件 / 文档                       │
│     ├─ 录音（转写）                      │
│     ├─ 图片                              │
│     └─ 文字描述                          │
│                                         │
│  ③ 下周计划（= 下周的承诺，会被追踪）       │
│                                         │
│  ④ 实体关联标签（Context Layer）          │
│     项目 · 产品 · 客户 · 人员             │
└─────────────────────────────────────────┘
```

## 三、周报生成流程：日常积累 + 周末聚合

用户选择的流程是 **「日常积累 + 周末聚合」**：

```
【日常】员工随时上传资料                    【周末】打开周报助理
   录音 / 视频 / 文件 / 描述一段话      →    AI 自动聚合本周所有资料
   AI 实时整理成「工作事项」                  生成周报草稿
   （资料持续沉淀，不必等周末）                  ↓
                                         AI 提醒完整度
                                         提醒补全上周承诺
                                            ↓
                                         员工核对补充 → 提交
```

这意味着员工侧有 **两个关键阶段**：

- **日常阶段**：资料采集与事项化（资料 → 工作事项）
- **周末阶段**：事项聚合为周报（工作事项 → 周报草稿）

## 四、员工侧（周报助理 weekly-assistant）页面设计

菜单结构（保留数字员工主导）：

```
周报助理 weekly-assistant
├── 数字员工对话 chat          ← AI 协作主入口（生成、提醒、问答）
├── 我的工作 my-work           ← 【新】日常资料与工作事项管理（日常阶段）
├── 本周周报 my-report         ← 【重构】周报生成与编辑（周末阶段）
├── 周报历史 history           ← 【重构】历史周报 + 评价与回复
└── 周报详情 report-detail     ← 【新】单份周报完整视图（含评价回复区）
```

### 4.1 数字员工对话 chat（生成阶段主入口）

**职责**：周报助理的主对话区。员工与 AI 协作的核心场所——上传资料、生成草稿、接受提醒、回答 AI 追问。

**AI 人格**：温暖的帮手。主动帮员工整理，主动提醒缺失。

**典型对话流**：

```
[AI] 👋 张三你好，本周我已经帮你归集了这些工作资料：
     · 8/5 录音：华达现场打印问题处理（12 分钟）
     · 8/6 文件：客户 B 接口联调说明.docx
     · 8/7 文字：AI Work 产品评审纪要
     共 5 条记录。需要我生成本周周报草稿吗？
     [生成周报草稿] [先看看本周工作]

[用户点击"生成周报草稿"]

[AI] ✅ 草稿已生成（第 32 周），工作完整度 78%。
     我发现两点可能需要补充：
     ⚠️ 华达现场打印问题（8/5）还没写进周报，要加入吗？
     ⚠️ 上周你承诺本周完成"客户 B 接口联调"，现在进展如何？
     [去补充] [直接看周报]

[用户] 客户 B 联调延期了，环境没准备好

[AI] 明白，我帮你记下延期原因。
     预计什么时候能完成？
     [本周内] [下周三前] [下周内] [日期未定]
```

**关键设计**：对话中的卡片（AiWorkCard）支持多种类型——action（带按钮的操作卡）、question（追问选项）、insight（风险提示）、deep-link（跳转）。

**关键点**：

- "上周承诺事项"有醒目标记，提醒员工跟踪

```
│ ▼ 问题与风险 (1)              │ │   客户B联调进展 │ │

│  └────────────────────────┘ │ └──────────────┘ │
│                              │                  │
│ [+ 添加事项]                  │ [让 AI 帮我完善]  │
└──────────────────────────────┴──────────────────┘
```

**生成阶段 AI 的核心行为**（你强调的重点）：

1. **提醒完整度**：78% 不够，AI 明确指出"差什么"（华达没写、承诺没确认、计划缺时间）
2. **提醒补全上周承诺**：右侧"上周承诺追踪"区块，员工提交前必须说明上周承诺事项的进展
3. **"让 AI 帮我完善"**：AI 逐项引导补全，完整度随之上升

**提交后**：状态 → SUBMITTED，进入主管（周报审核）的审核队列。

## 五、评价与回复体系设计

用户选择 **「评分 + 评语」**。这是周报提交后，主管（通过周报审核 Agent）对周报的反馈，员工可回复。

### 5.1 评价结构

```typescript
interface AiWorkReportReview {
  reviewerId: string; // 评价人（主管）
  reviewerName: string; // "李经理"
  reviewerRole: string; // "产品研发部负责人"
  score: number; // 总分 4.2 / 5.0
  comment: string; // 整体评语
  itemScores: AiWorkItemScore[]; // 逐项评价
  reviewedAt: string; // 评价时间
}

interface AiWorkItemScore {
  itemTitle: string; // "客户B联调"
  score: number; // 3.5
  comment: string; // "注意环境依赖的前置确认"
}

interface AiWorkReply {
  authorId: string;
  authorName: string;
  authorRole: 'employee' | 'manager';
  content: string;
  createdAt: string;
}
```

### 5.2 评价是后台 Agent 自动产出，数字员工负责呈现

| 环节 | 谁在做 | 数字员工的角色 |
| --- | --- | --- |
| **生成草稿** | 后台生成 Agent | 周报助理**调用**它，转述"草稿好了" |
| **完整度检查** | 后台完整度 Agent | 周报助理**呈现**结果"78%，缺这两项" |
| **综合评分** | 后台评分 Agent（自动） | 周报审核**呈现**"评分 4.2" |
| **挖掘模式** | 后台洞察 Agent（自动） | 周报审核**呈现**"连续 3 周无进展" |
| **逐项评价建议** | 后台评分 Agent（自动） | 周报审核**呈现**给主管参考 |
| **员工查看评价** | — | 周报助理**呈现**评价、帮员工理解改进 |

**后台洞察 Agent 的关键能力——挖掘模式**（你举的例子，自动产出后呈现给主管）：

```
该员工连续 3 周对华达客户写"持续跟进"，但无实质进展描述。
可能存在的问题：
  · 客户配合度不足
  · 技术方案未对症
建议：
  · 本周内安排现场二次确认
  · 评估是否需要升级技术支持
评分建议：3.0（进展不足）
逐项评价建议：华达跟进项 → "建议补充具体沟通结论"
```

> **注意**：以上结论是后台 Agent **自动生成**的。周报审核（数字员工）只是查询并呈现给主管，它本身不"思考"评分。主管看到后可以采纳、修改，或直接和周报审核对话追问更多细节。
