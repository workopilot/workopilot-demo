# 喔壳 Demo

以数字员工为业务入口、使用 Mock 数据演示业务的中文前端系统，用于产品演示、需求验证和交互方案评审。

**数字员工承载业务办理，应用承载业务配置；对话和业务页面共同完成同一套业务流程。** 交付目标是可运行、可操作、可连续演示的业务闭环。

> 开发前必读：[Agent 开发约定](AGENTS.md) · [喔壳 Demo 开发规范](docs/Demo开发规范.md)。完整规范统一在 `docs/Demo开发规范.md` 维护，所有 Agent 和开发者开始相关开发前应完整阅读。

## 产品组织

| 入口 | 面向角色 | 承载内容 |
| --- | --- | --- |
| 数字员工 → 对话 | 业务用户 | 使用自然语言查询、发起和处理业务 |
| 数字员工 → 业务菜单 | 业务用户 | 查询列表、查看详情、填写表单和继续处理记录 |
| 应用 → 业务配置 | 业务管理员 | 维护共享资源、业务规则、模板和权限等 |
| 个人设置 | 当前用户 | 维护个人通知及展示偏好 |

按开发规范，每个数字员工的第一个菜单统一为“对话”，进入后默认打开该页面。同级业务菜单按业务对象或结果命名，例如“我的会议”“客户”“商机”“历史报告”。

判断页面归属时，区分“办理一笔业务”和“配置业务如何运行”。数字员工与应用复用业务数据和配置，不要求机械地一一对应。

以会议场景为例，目标流程是：

```text
管理员配置会议室与预约规则
→ 用户通过会议助理提出预约需求
→ 补齐信息、检查冲突、确认预约
→ 创建 Mock 会议记录
→ 在“我的会议”查看、改期或取消
→ 再次对话查询得到更新后的结果
```

以上为开发与验收目标，不表示所有既有页面已完成统一，或会议场景已全部实现。

## 业务场景与演示边界

仓库包含以下业务方向的页面、数据和交互实现，具体完成范围以对应模块和场景文档为准：

| 业务方向       | 涉及内容                                         |
| -------------- | ------------------------------------------------ |
| 汇报与审阅     | 工作素材、报告草稿、人工补充、提报、审阅和分享   |
| 项目管理       | 制度与模板、立项、项目执行、成果物、风险与干预   |
| 合同管理       | 合同对话、档案、授权和相关业务衔接               |
| 工单与巡检     | 工单处理、调度、行程、巡检计划及规则配置         |
| 销售管理       | 客户跟进、商机和销售工作台                       |
| 智能审核与填报 | 审核规则与方案、附件分类、填报脚本和执行记录     |
| 平台管理       | 数字员工配置、能力资源、知识档案、租户及运营管理 |

业务通过前端 Mock 数据模拟。对话可以使用预设意图、示例问题和模拟执行过程，无需接入真实大模型、数据库或第三方系统。部分菜单仍为占位页面，功能入口不代表生产能力已经接通。

默认在内存中保存业务状态，刷新后重置；部分既有模块使用浏览器会话或本地存储，刷新不一定清空，应按模块说明或重置入口恢复演示。新增持久化必须说明保存范围与重置方式。

## 快速开始

### 环境准备

- **Node.js**：当前锁文件中的 Vite 要求 `^20.19.0 || >=22.12.0`。
- **pnpm**：使用根目录 `package.json` 指定的 `10.22.0`。
- 在仓库根目录执行安装、启动和构建命令。

现有 `.node-version` 为 `22.1.0`，低于当前 Vite 要求。使用版本管理工具时，请手动选择满足上述范围的 Node.js。

### 安装与启动

```bash
pnpm install
pnpm dev:antd
```

首次启动前按 [AGENTS.md](AGENTS.md) 确认部署子目录，并在仓库根目录创建本地 `.env`（已忽略，不提交 Git）：

```dotenv
WK_DEMO_SUBDIRECTORY=wkdemo
```

例如 www.xxx.com/**wkdemo**/index.html；也可以改为其他名称，或设为 `WK_DEMO_SUBDIRECTORY=` 使用根目录。已有文件直接使用，不重复初始化。

默认开发端口为 `5666`，上述配置的基础路径为 `/wkdemo/`，实际地址以终端输出为准：

- [本地 Demo 首页](http://localhost:5666/wkdemo/)
- [Mate 用户端工作台](http://localhost:5666/wkdemo/app/mate/home)

管理端登录使用前端模拟认证，可在登录页选择预置账号。用户端演示路由允许免登录访问。

业务 Mock 主要位于 `apps/web-antd/src/api/`。仓库仍保留框架的 `apps/backend-mock/`，当前开发配置启用了 Nitro Mock 插件；新增业务按前端 Mock 方式实现，无需另建后端服务。

图标由 Iconify 在线按需加载，演示环境需要能够访问图标服务。

### 常用命令

| 命令 | 用途 |
| --- | --- |
| `pnpm dev:antd` | 启动主要业务前端 |
| `pnpm build:antd` | 构建业务前端，默认产物位于 `apps/web-antd/dist/` |
| `pnpm --filter @vben/web-antd preview` | 本地预览已构建的前端 |
| `pnpm check:type` | 执行工作区类型检查 |
| `pnpm test:unit` | 执行仓库现有单元测试 |

开发、构建及发布脚本统一读取根目录 `.env`。路由和资源路径自动跟随该配置；修改后重启开发服务或重新构建，实际地址以终端输出为准。生产默认使用 hash 路由，可通过 `/wkdemo/index.html` 访问。

## 开发方式

1. 阅读 [AGENTS.md](AGENTS.md) 和 [完整开发规范](docs/Demo开发规范.md)，明确业务职责与演示范围。
2. 划分“对话 + 业务菜单”和“应用配置”，定义业务对象、状态和关联关系。
3. 按业务拆分 Mock 数据、接口方法和类型，再让对话、列表、详情与表单共同调用。
4. 复用现有组件和布局，同步员工注册、菜单、路由和默认跳转。
5. 串联主流程与异常场景，记录模拟范围、重置方式和验证结果。

实现时重点遵循以下约定，细节以完整规范为准：

- **数据联动**：对话、列表、详情和统计读取同一份业务状态。创建、修改、取消等操作必须实际更新记录，应用配置应影响相关业务行为。
- **Mock 接口**：数据放在 `src/api/mock-data-<domain>.ts`，业务方法放在 `src/api/<domain>.ts`，类型放在 `src/types/<domain>.ts`。复用 `createMockResponse`、`mockDelay`，返回 `{ code, data, message }`。
- **组件与样式**：使用 `<script setup lang="ts">`；显式导入 Ant Design Vue 组件，使用 `<Button>` 等 PascalCase 标签。优先复用 Vben 表单、弹窗、表格及既有业务布局。
- **图标**：使用 `@iconify/vue` 或 `@vben/icons` 的 `IconifyIcon`，优先 Lucide；不恢复全量图标包或 `icon-[...]` 写法。
- **路由**：后台模块放在 `src/router/routes/modules/`；Mate 页面沿用 `core.ts` 的独立用户端布局。员工注册与菜单需核对 `src/api/mock-data-mate.ts`。
- **文件边界**：子组件和弹窗分别放在模块的 `components/`、`modals/`，复杂逻辑按职责拆分。不修改 `packages/@core/` 和 `apps/web-antd/src/views/_core/`，不新增其他 UI 模板应用、后端或国际化流程。
- **改动范围**：历史实现与规范不一致时，按本次任务范围逐步统一；格式化仅覆盖本次修改文件。

## 验证与交付

每次开发至少检查相关业务的连续演示流程：

```text
应用配置 → 对话操作 → 业务记录 → 详情与后续操作 → 再次查询
```

确认菜单与默认跳转正确、跨页面状态一致、关键操作有必要的加载和结果反馈，并覆盖缺少信息、冲突、失败、取消等场景。演示应能够恢复初始状态并重复执行。

按改动范围执行类型检查、构建及相关测试。交付时说明已实现能力、模拟边界、重置方式和检查结果；未运行的检查需明确说明，历史错误与本次新增问题分别记录。完整验收清单见 [开发规范第 9 节](docs/Demo开发规范.md#9-验收清单)。
